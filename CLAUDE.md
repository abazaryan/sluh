# Слух — карточки с голосовым ответом

Личное приложение для интервальных повторений (как Anki), где пользователь отвечает голосом, а оценка (Снова / Трудно / Хорошо / Легко) выставляется автоматически по точности и скорости ответа.

Полная спецификация и этапы: `docs/SPEC.md`. Текущее состояние проекта: `docs/STATUS.md`. Рабочий прототип (один HTML-файл): `prototype/sluh.html`.

## Роли

- Владелец продукта — пользователь (Pooya). Он даёт идеи, тестирует на телефоне и принимает решения. Код он писать не планирует.
- Реализацию целиком делаешь ты: архитектура, код, тесты, сборка, публикация.
- Общайся с пользователем по-русски. Объясняй коротко и простыми словами: что сделано, что проверить, что нужно от него.

## Устройства пользователя (подтверждено)

- Android-смартфон, Chrome — основное устройство для занятий.
- Ноутбук Windows, Microsoft Edge.

## Стек

- Vite + TypeScript (strict) + React.
- IndexedDB через Dexie — колоды, карточки, медиафайлы, журнал ответов.
- `ts-fsrs` — планировщик интервалов. Алгоритм самостоятельно не писать.
- Импорт APKG: JSZip + sql.js (wasm-файл хранится вместе с приложением, не грузится с CDN).
- Распознавание: Web Speech API (`SpeechRecognition` / `webkitSpeechRecognition`), язык `fr-FR`.
- Тесты: Vitest для всей «чистой» логики.
- PWA: vite-plugin-pwa (с этапа 4).
- Хостинг: GitHub Pages через GitHub Actions (HTTPS обязателен для микрофона).

Новые зависимости сверх этого списка — только с объяснением, зачем они нужны.

## Архитектурные правила

- Чистая логика отдельно от UI, в `src/core/`: сверка ответа, оценка, разбор колоды, адаптер планировщика. У каждого модуля — юнит-тесты.
- Работа с браузерными API (микрофон, синтез речи, IndexedDB) — в `src/platform/`, за тонкими интерфейсами, чтобы логику можно было тестировать без браузера.
- UI — в `src/ui/`. Интерфейс на русском языке.
- Никаких API-ключей в клиентском коде. Если понадобится внешний API (например, Gemini), — только через отдельный серверный прокси, и сначала обсудить с пользователем.
- Данные пользователя хранятся локально, на сервер не отправляются (кроме звука, который браузер сам передаёт в свою службу распознавания — об этом пользователь знает).

## Порядок работы

- Работай по этапам из `docs/SPEC.md`. Не начинай следующий этап, пока пользователь не подтвердил предыдущий.
- В конце каждого этапа: прогон тестов и сборки, короткий отчёт пользователю (что сделано, что он должен проверить на телефоне, известные ограничения).
- В конце каждого этапа обновлять `docs/STATUS.md` (где мы, отличия от SPEC.md, ссылки, результаты тестов и сборки, что проверено на телефоне и что нет, известные проблемы, открытые решения) и коммитить его вместе с остальными изменениями этапа.
- Разделяй в отчётах: что проверено (тестами или сборкой), что не проверено, что является предположением.
- Перед действиями, которые требуют аккаунтов пользователя (создание репозитория GitHub, включение Pages, вход через `gh`), объясни по шагам, что он должен сделать, и дождись подтверждения.
- Коммиты небольшие, с понятными сообщениями на английском.

## Что уже известно

- Прототип в `prototype/sluh.html` работает как одна страница: сверка по словам (расстояние Левенштейна по словам, без учёта регистра, пунктуации и, по настройке, акцентов), замер времени до начала речи, предложение оценки, ручная коррекция, журнал в localStorage.
- Этап 1 принят 07.10.2026: приложение на https://abazaryan.github.io/sluh/ (репозиторий abazaryan/sluh, публичный). На Android Chrome распознавание работает: 28 ответов из 28 распознаны.
- В коммитах — только служебная почта GitHub `134600070+abazaryan@users.noreply.github.com` (прописана в настройках git этого репозитория). Личную почту в публичный репозиторий не отправлять.
- Внутри встроенного окна claude.ai микрофон на Android Chrome не запустился (зависание на старте, без ошибки). Наиболее вероятная причина — политика разрешений встроенного окна; не подтверждено. Поэтому приложение нужно размещать на собственном HTTPS-адресе.
- Аудио для карточек пользователь генерирует сам через Gemini 3.8 Flash TTS; аудио будет приходить внутри APKG. Встроенный синтез речи браузера — только запасной вариант.
- Пороги оценки (Легко ≤ 2,5 с, Хорошо ≤ 6 с, Снова при точности < 60 %, не выше «Трудно» при точности < 85 %, +0,3 с на каждое слово сверх 4) — начальные предположения. По первому журналу (28 ответов) пользователь с оценками согласен, пороги пока не меняем; калибровать на более трудных карточках.
